# 페이지 소스 점검

홈페이지는 화면에 안 보여도 페이지 소스는 누구나 볼 수 있다(크롬 주소창에 `view-source:` + 주소, 또는 맥 ⌥⌘U / 윈도우 Ctrl+U). AI로 만든 사이트는 작업 중에 남긴 메모가 그대로 배포되는 일이 많다. 이 스킬은 그걸 찾아서 지운다.

## 1. 점검 대상 정하기

- 사용자가 주소를 주면 그 주소와, 같은 사이트 안의 링크된 페이지(최대 20개)를 내려받아 점검한다. `curl -sL <주소>`로 받는다.
- 사용자가 폴더를 주면 그 안의 `.html`, `.css`, `.js` 파일을 점검한다.
- 점검만 한다. 사용자가 고쳐 달라고 하기 전에는 파일을 바꾸지 않는다.

## 2. 찾을 것 (위험한 순서)

| 등급 | 무엇 | 예 |
|---|---|---|
| 높음 | 비밀키·토큰 | `sk-`, `AKIA`, `AIza`, `ghp_`, `secret`, `token`, `apiKey`, `service_role` |
| 높음 | 개인정보 | 휴대폰 번호(010-), 개인 이메일(@gmail 등), 주민번호 형식, 실제 고객·신청자 이름 |
| 중간 | 작업 메모 주석 | `<!-- -->`, `/* */`, `//` 안의 날짜·버전(3차, v12), 사람 이름, "고객이 말한", "신청서", "TODO", "임시", "테스트" |
| 중간 | AI와 주고받은 흔적 | "요청하신 대로", "Claude", "ChatGPT", "프롬프트", "수정본", 지시문 같은 문장 |
| 중간 | 숨겨 둔 내용 | `display:none`, `hidden` 속성 안의 문장, 화면 밖으로 밀어 둔 텍스트 |
| 낮음 | 내부 경로·도구 흔적 | `/Users/`, `C:\`, `localhost`, 스테이징 주소, 소스맵(`.map`) 링크 |
| 낮음 | 공개된 설정 파일 | `/.env`, `/.git/HEAD`, `/netlify.toml`, `/package.json`이 열리는지 (`curl -s -o /dev/null -w '%{http_code}'`) |

폼의 `type="hidden"` 입력(예: `form-name`)과 스팸 방지용 숨김 칸, 아이콘의 `aria-hidden`은 정상이니 빼고 보고한다.

## 3. 보고 형식

대표님이 읽을 수 있게 쉬운 말로 쓴다.

1. 한 줄 결론: "급히 지울 것 N개, 지우면 좋은 것 N개"
2. 표: 등급 / 파일과 줄 번호 / 찾은 내용(비밀키는 앞 4자리만 보이고 나머지는 가림) / 왜 문제인지 한 줄
3. 비밀키가 나왔으면 "소스에서 지우는 것만으로는 부족하고, 그 키를 발급한 곳에서 키를 새로 바꿔야 한다"고 맨 위에 적는다.

## 4. 고치기 (사용자가 원할 때만)

- 원본을 `원본-백업/`에 복사한 뒤 고친다.
- `<style>` 안의 `/* */` 주석과 HTML 주석 `<!-- -->`은 지운다. `<script>` 안의 주석은 문자열 안의 `//`(예: `https://`)를 건드리지 않도록 한 줄씩 확인하고 지운다.
- 숨겨 둔 문장, 개인정보, 비밀키는 지우고, 그 자리에 필요한 게 있으면 사용자에게 묻는다.
- 고친 뒤 다시 2번 점검을 돌려 0개인지 확인하고, 고치기 전과 후의 화면이 같은지 확인한다(가능하면 스크린샷 비교).
- 배포는 하지 않는다. 고친 파일 위치와 배포 방법만 알려 준다.

## 5. 다음부터 안 남기는 법

보고 끝에 한 줄 붙인다: "AI에게 사이트를 맡길 때 '작업 메모는 소스에 주석으로 남기지 말고 따로 정리해 줘'라고 처음에 말해 두면 같은 일이 줄어요."
